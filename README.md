 C++ 全栈分布式即时通讯系统

项目简介
这是一个基于现代 C++ (C++11及以上) 开发的全栈分布式即时通讯项目。前端采用 Qt 框架实现了精美的仿微信气泡聊天界面，后端采用微服务分布式架构设计，能够支持高并发连接与多节点部署，具备极高的稳定性和扩展性。本项目不仅包含复杂的网络通信逻辑，还深入应用了多种设计模式及现代化内存管理机制。


用户认证：支持用户注册、登录，并基于 Node.js 搭建了邮箱验证码派发服务。
好友管理：支持搜索好友、发起好友申请、好友认证流程及联系人列表动态展示。
实时通信：支持一对一气泡聊天，聊天记录展示，消息实时推送。
状态同步：实现用户在线状态管理，支持多节点下的“单点登录”检测、单服踢人及跨服踢人逻辑。
连接保活与高可用：已实现双向心跳检测机制（Heartbeat）。服务端能够精准识别并清理因网络波动、断网、应用异常退出导致的“僵尸连接”；客户端支持断线重连逻辑，极大提升了网络容灾能力和服务器资源利用率。

架构设计
后端采用分布式微服务架构，服务节点间通过 **gRPC** 进行高效的 RPC调用
GateServer (网关服务)：对外提供 HTTP 服务，负责处理用户的注册、登录请求。在用户登录时，通过向 StatusServer 查询当前可用 ChatServer 实例，实现客户端长连接的**负载均衡**。
ChatServer (聊天服务)：核心业务节点，采用基于 Asio 的 TCP 可靠长链接异步通信。内部根据 CPU 核数封装 `io_context` 线程池以提升并发处理性能，负责消息的高效收发与分发。
StatusServer (状态服务)：负责管理全网用户的在线状态、路由信息以及各 ChatServer 的负载情况。
VerifyServer (验证服务)：独立处理验证码生成与派发等安全验证业务。
数据存储层：使用 **MySQL** 存储持久化数据（如用户信息、好友关系），使用 **Redis** 处理高频缓存数据及分布式状态。

技术栈
后端开发：C++11/14/17, Asio 异步网络库, 多线程与并发编程
前端开发：Qt 框架 (网络模块, 信号槽机制, MVC模型, 自定义UI渲染如 `QPainter`, `GridLayout`)
RPC 与序列化：gRPC, Protobuf, JSON
中间件与数据库：MySQL (C++ Connector), Redis, Node.js (用于邮箱认证)

技术亮点 & 核心设计
1. 连接保活与高可用：已实现双向心跳检测机制（Heartbeat）。服务端能够精准识别并清理因网络波动、断网、应用异常退出导致的“僵尸连接”；客户端支持断线重连逻辑，极大提升了网络容灾能力和服务器资源利用率。
2. 中间件与连接池封装：为避免多线程竞争与资源过度消耗，自主封装了 MySQL 连接池、Redis 连接池以及 gRPC 连接池。管理层采用单例模式，底层通过生产者消费者模型及 RAII 机制安全地调度可用连接，内置定时心跳防断开保活。
3. 高并发线程池：采用 C++11 风格实现自定义线程池，内部使用 `std::packaged_task` 打包任务，配合 `std::bind` 实现伪闭包，结合 `std::future` 获取异步执行结果。
4. 架构解耦与分离：严格遵循单一职责原则。逻辑层与网络层解耦（Actor模式思想）；客户端采用 MVC 架构并实现网络线程、逻辑处理线程与 UI 渲染线程的分离；服务器数据处理引入发送/接收/逻辑多队列解耦。
5. 可靠的心跳超时淘汰机制：基于 Asio 的 steady_timer 和时间戳机制实现了高效的会话状态管理。通过定时轮询或惰性检查检测客户端心跳包（Ping/Pong 协议），利用智能指针的引用计数（std::shared_ptr / std::weak_ptr）安全地管理 Session 生命周期，避免了定时器回调时的野指针和内存泄漏问题。

性能指标
经过详尽的 Ping-Pong 协议测试和高强度压力测试：
* 低延迟：在高负载状态下，数据收发效率依然稳定在 10ms 以下，无明显丢包。
* 高并发：单台 ChatServer 节点可稳定维持 **8,000 ~ 20,000** 个并发活跃长连接。
* 可扩展：支持多服务器分布式部署，可通过简单增加 ChatServer 节点横向扩展整体系统吞吐量。
